# Datasets

All datasets used by the platform are described here, verified directly against the files present in
`eoha-prototype/data/` and the actual `Papa.parse()` calls that load them.

:::caution No disease validation dataset
The prototype repository currently provides environmental observations and population context, but
no linked malaria case counts, NCD outcomes, or health-survey labels. **Validation data has not been
acquired.** The environmental variables are inputs for exploratory indicators; their relationship
to disease outcomes has not been validated in this prototype.
:::

---

## Primary dataset — the file actually loaded

:::caution Two similarly-named files exist; only one is loaded
`eoha-prototype/data/` contains **two** CSVs with almost identical names. The one every script
actually loads (`Limpopo_Risk_Jan25_Jan26_Safe.csv`, no trailing digit) is **nationwide**, despite its
filename. The genuinely Limpopo-only file (`Limpopo_Risk_Jan25_Jan26_Safe1.csv`, trailing `1`) exists
in the same folder but is never referenced by any script — it is the one the original version of this
page described.
:::

**File:** `Limpopo_Risk_Jan25_Jan26_Safe.csv` (loaded by the malaria dashboard, reports page, and NCD
observation page)

| Property | Value |
|----------|-------|
| Records | 58,085 |
| Time range | January 2025 – January 2026 |
| Temporal resolution | Monthly |
| Spatial coverage | **All 9 South African provinces** (not just Limpopo) |
| Spatial unit | Ward |
| Wards | 4,468 |
| Source | Bundled directly in the `eoha-prototype` repo; not regenerated by `eo-datapipeline` (see caution below) |

### Column reference (as loaded)

| Column | Type | Unit | Description |
|--------|------|------|-------------|
| `Month` | string | — | Month-year label (e.g. `Jan 2025`) |
| `WardID` | string/number | — | Ward identifier |
| `WardLabel` | string | — | Ward code (e.g. `LIM331_1`) |
| `Municipali` | string | — | Municipality name |
| `Province` | string | — | Province name |
| `latitude` | float | degrees | Ward centroid latitude (WGS84) |
| `longitude` | float | degrees | Ward centroid longitude (WGS84) |
| `LST_Surface_C` | float | °C | Land surface temperature |
| `Air_Temp_C` | float | °C | Near-surface air temperature |
| `Soil_Moisture` | float | m³/m³ | Volumetric soil moisture |
| `NDWI_Water` | float | index | Normalised Difference Water Index |
| `Habitat_Vegetation_Index` | float | index | Vegetation density |
| `Agric_Percentage` | float | fraction | Agricultural land cover (0–1) |
| `Population_Density_Per_KM2` | float | persons/km² | WorldPop population density |
| `Habitat_Class_Code` | float | code | ESA WorldCover class |

### The unused Limpopo-only file

**File:** `Limpopo_Risk_Jan25_Jan26_Safe1.csv` — 7,385 records, 13 months, genuinely Limpopo-only
(22 local municipalities). Same column set minus `WardID` and `Province`. Not loaded by any current
script — dead data in the repo.

### Relationship to `eo-datapipeline`

Neither CSV is produced by, or synced from, `eo-datapipeline`'s output. That pipeline writes to a
PostgreSQL database (`zone`, `malaria_observation` tables), reachable only via `eoha_backend`'s REST
API — a separate path with no code connection to either file described here. See
[System Architecture →](/docs/architecture/system-architecture) for the full as-built diagram.

## Boundary datasets

| File | Content | Format | Schema | Actually used for |
|------|---------|--------|--------|--------------------|
| `africa-countries.geo.json` | African country polygons | GeoJSON | Natural Earth–style (`properties.name`) | NCD page country shapes |
| `South_Africa_ADM1.geojson` | South Africa provincial boundaries | GeoJSON | **geoBoundaries** (`properties.shapeName`) | NCD page province shapes — drill-down is currently broken because the code expects GADM's `NAME_1` property instead (see [Modules → NCD Risk](/docs/modules/ncd)) |
| `South_Africa_ADM3.geojson` | South Africa municipality centroids | — | — | **Does not exist in the repo.** The municipality drill-down this file would power is non-functional; the code's own comment confirms this |

## EO source collections actually used (`eo-datapipeline`)

The dashboard's CSV files are static and don't reflect any live GEE collection. The collections below
are what `eo-datapipeline`'s `etl_pipeline.py` actually queries when it runs — a different, real
pipeline whose output lands in PostgreSQL, not in either CSV described above:

| GEE Collection ID | Product | Variables extracted |
|-------------------|-----------|-------------------|
| `MODIS/061/MOD11A1` | MODIS Terra | Land surface temperature |
| `MODIS/061/MOD13Q1` | MODIS Terra | NDVI |
| `MODIS/061/MOD09GA` | MODIS Terra | NDWI (manually computed normalized difference) |
| `ECMWF/ERA5_LAND/HOURLY` | ERA5-Land reanalysis | Air temperature, soil moisture |
| `WorldPop/GP/100m/pop` | WorldPop | Population density |
| `ESA/WorldCover/v100` | ESA WorldCover | Habitat class, cropland mask |

Sentinel-2, SMAP, and WorldClim — cited in earlier drafts of this page — are not used by any script
in any of the three repos.

## Data update frequency

| Dataset | Actual behaviour |
|---------|---------|
| `eo-datapipeline` → PostgreSQL | Runs monthly via GitHub Actions cron; output reachable only through `eoha_backend`'s (currently unconsumed) REST API |
| Dashboard CSV files (`eoha-prototype/data/*.csv`) | Static — bundled in the repo, not regenerated by any pipeline or scheduled process |
| NCD country/province scores | Static — hardcoded in `pages/ncd-page.html`'s JavaScript |
| Boundary files | Static |

## Accessing the data

The dashboard's CSV/GeoJSON files are stored in `eoha-prototype/data/` and loaded client-side by
PapaParse/`fetch` at runtime — see
[`eoha-prototype/SUMMARY.md`](https://github.com/MEDICONSORTIUM/eoha-prototype/blob/main/SUMMARY.md).
The live pipeline's output is only reachable through `eoha_backend`'s REST API
(`GET /api/zones`, `GET /api/malaria-observations`) — see
[`eoha_backend/SUMMARY.md`](https://github.com/MEDICONSORTIUM/eoha_backend/blob/main/SUMMARY.md).
For the GEE extraction logic itself, see [Google Earth Engine →](/docs/data/google-earth-engine).
